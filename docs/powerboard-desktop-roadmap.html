PowerBoard v2 — Desktop-First Roadmap

The corrected, upgraded version of the six-point brief: what PowerBoard becomes, every architecture decision locked with rationale, what the original prompt was missing, and the phased path to a TestFlight-installed macOS app.

2026-07-04 · Prepared by Claude (Fable) · Execution checklist lives in tasks/todo.md · Agent brief: AGENTS.md

The corrected brief (the upgraded prompt)

PowerBoard is a desktop-first, offline-first, agent-first visual workspace for one person + their agents. One canvas and one object model serve two jobs: hi-fi app mockups (device artboards, semantic elements, screenshot tracing, React/Tailwind export) and diagrams (flowcharts, org charts, process flows, schematics, stickies, freehand ink — the useful core of Miro, Visio, and Excalidraw merged MECE). It ships as a signed macOS app via TestFlight, stores boards as local files with versioned iCloud backups, exposes a hyper-reliable MCP served by the installed app itself, and treats agents as first-class co-editors whose work is a designed, delightful surface to watch. Supabase cloud is demoted to an optional sync target for a later online/sharing phase.

Two corrections to the original wording. First, "convert to a macOS app" and "offline desktop first" are one workstream, not two — the desktop shell is only trustworthy if storage goes local-first in the same move, so points 1 and 5 merge. Second, "also like Miro/Visio/Excalidraw" is not a second product bolted on: the existing schema (elements, connectors, semantic roles) already generalizes, so diagramming is an extension of the connector + element model, never a parallel canvas. That's what keeps the feature set MECE.

What the original prompt was missing

P0 A live data-loss bug in the browser fallback

The browser-local mode stores all projects, including base64 screenshot assets, in a single localStorage key (apps/web/src/api.ts). That's the exact ~5 MB-quota pattern that destroyed real user data in Lamonade and Shotapp. One realistic screenshot import can silently kill saving. Fixed first (IndexedDB + loud failure states) before anything is built on top.

Gap Undo/history dies on restart

Undo stacks are in-memory only. An offline-first desktop app needs a persisted per-board operation log — which is also the cheap door-opener for the future sharing/sync phase and the unit the iCloud backups snapshot. Designed in now (decision D6), so "later online" doesn't require a rewrite.

Gap Migration of existing cloud boards

Boards currently live in Supabase. The desktop app gets a one-time first-run importer (cloud → local files, read-only against the cloud) so nothing is stranded when the source of truth flips.

Gap App identity & release plumbing

Bundle id, icon, native menu bar, single-instance behavior, entitlements, and a Mac Installer Distribution certificate (the one signing asset you don't have yet — mintable via your ASC API key). All specified in Phase 1.

Gap Diagram-grade exports

PNG/spec/React-Tailwind serve mockups; diagrams want SVG, PDF, and Mermaid export (Mermaid especially — it lets agents round-trip your diagrams as text). Added in Phase 4.

Good news Credentials & pipeline are fully in place

ASC API key 998DV58D4V (issuer id in Habeat's scripts/.env, iCloud backups of keys exist), Team R5Z99F8UNV, Apple Distribution certificate already in the keychain, and two proven fastlane TestFlight pipelines (Habeat, Vellum) to model PowerBoard's beta lane on. Nothing to hunt down.

Locked decisions

#DecisionWhy (and what was rejected)
D1Electron shell, Mac App Store build → TestFlightThe existing Node server (Express + WebSocket + MCP + sharp PNG export) runs unmodified in Electron's main process — the installed app becomes the single daemon that serves UI, storage, and MCP together. Tauri or a native Swift shell would mean porting ~2.2k lines of server logic or smuggling a Node sidecar past the App Sandbox. Fallback if MAS sandbox fights back: Developer ID + notarized DMG (still one-click installable; loses TestFlight only).
D2com.lamonade.powerboard, Team R5Z99F8UNV, fastlane beta laneMatches the CentsCheck bundle-id convention and reuses the proven Habeat/Vellum lane shape with the shared ASC API key.
D3Local files become the source of truthBoards as JSON in the app's user-data dir via the existing local storage mode — the pivot reuses shipped code. Supabase drops to optional sync (mirror mode is the bridge when the online phase arrives).
D4iCloud backup, not iCloud syncVersioned, pruned snapshots to iCloud Drive on quit + debounced autosave, with an in-app restore picker. True multi-device sync is deferred to the online phase — doing it now buys conflict bugs with no second device to justify them.
D5One object model for mockups and diagramsA diagram shape is an element type; there is exactly one connector system. "Mockup" vs "Diagram" is a tool-palette preset, never a document fork. This single rule is what keeps Miro/Visio/Excalidraw merging MECE.
D6Persist the operation log now; sharing laterFixes undo-across-restarts today, gives backups a clean unit, and leaves the door open for share links / co-editing without committing to a CRDT before there's a second user.

Phases

0

Foundation & P0 fixes

Kill the localStorage data-loss pattern (IndexedDB + loud save failures). Split the 2.6k-line App.tsx into modules. Extract design tokens to CSS variables with a dark-mode layer. No visible behavior change; everything after builds on this.

1

macOS app on TestFlight (your #1)

Electron shell running the existing server in-process, native menus, app icon, local file storage in user-data, first-run cloud-board importer, electron-builder mas + entitlements, fastlane beta lane, TestFlight install verified end-to-end with a realistic board round-trip.

2

Offline-first storage + iCloud backup (your #5)

Persisted op-log (undo survives restarts), versioned iCloud Drive snapshots with pruning, in-app restore picker, loud backup-failure states. Cloud modes stay compiled + canary-tested but off by default.

3

UI/UX overhaul (your #2)

Full taste pass (type ramp, 4/8 grid, one accent, designed dark mode). Canvas feel: inertial pan, snapping + alignment guides, marquee select, inline text editing. Agent presence as a designed feature — live agent cursor, human-readable activity feed, animated edit highlights, session timeline — so watching agents work is the delight you asked for. ⌘K command palette, shortcut overlay, designed empty/loading/error states everywhere, onboarding starter board.

4

Diagramming (your #4)

Connector v2, then shape/sticky/ink element types, frameless sections, auto-layout commands, palette presets ("Mockup" / "Diagram"), SVG + PDF + Mermaid export.

5

MCP hyper-reliability (your #3)

MCP served by the installed app (agents always reach the board you're looking at), atomic batch_operations with preview/rollback, idempotency keys, 2am-quality error messages with machine-readable codes, reconnect/resume, health/heartbeat tool, and a 500-operation agent soak test that must end validate_board-clean.

6

Online & sharing (parked until you say go)

Supabase sync replaying the persisted op-log, share links, human presence. The conflict strategy (CRDT vs single-writer lease) gets decided at that design moment — not paid for now.

Risks worth naming

  • MAS sandbox × Electron is the riskiest single step (entitlements, signing sharp's native dylibs, localhost server inside the sandbox). It's well-trodden but fiddly; the Developer ID + notarized DMG fallback is explicitly held ready (D1) so "installed on your Mac" is guaranteed even if TestFlight specifically fights back.
  • DOM canvas performance is fine at mockup scale; big diagrams (500+ nodes) may eventually want canvas-layer rendering for connectors. Measured before optimized — no speculative rewrite.
  • Scope gravity: Miro/Visio/Excalidraw are three funded products. The matrix above is the fence: anything not in it (video chat, voting, infinite template galleries) is out until you ask.
