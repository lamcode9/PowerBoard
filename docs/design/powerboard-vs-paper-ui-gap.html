PowerBoard vs paper.design

A UI-and-design gap read, and the fixes that shipped from it.

2026-07-29 · benchmark: paper.design editor · scope: visual and interaction craft only

The finding in one line: PowerBoard's gap to Paper was never the canvas — it was the inspector. One selected element rendered a panel 1481px tall inside a 626px column, built from 21 flat fields and 9 range sliders. Paper puts X / Y / rotation / W / H / flip in two ~28px rows. That single control choice cascaded into everything else that felt unfinished.

How this was measured

Paper.app is installed on this machine but access to drive it was declined, so the Paper side is read from the editor capture on paper.design (a real screenshot of the shipping app: layer tree, tool rail, and a Document / Layout inspector) plus the prior deep-dive in Documents/paper-design-gap-plan-2026-05-07.md, which was written with the live app and its MCP surface in hand. The PowerBoard side is measured, not estimated — the running app at 1280×720, dark theme, with one element selected, queried through the DOM.

What was actually wrong

1. The inspector — the dominant gap

  • Range sliders for spatial values. NumberField rendered input[type=range] and input[type=number] for every numeric property. A slider can never land on an exact coordinate, and it cost four stacked rows per value. Nine of them in one panel.
  • No grouping. 21 controls in one undifferentiated column — nothing had rank, so everything past the fold was effectively gone.
  • Machine metadata led the panel. Internal ID and Path were fields #1 and #2, above Name. Paper never shows an id in the design surface.
  • Every label was 11px UPPERCASE BOLD, stacked above its control — roughly doubling each row and leaving no typographic room to distinguish a heading from a field.
  • z-index exposed as a 0–999 box labelled "Layer". That is the data model leaking, not a control: depth is Forward / Back.
  • Colour rows were broken. .color-field declared three columns (1fr 42px minmax(0,1fr)) for a full-width label plus two inputs, so the hex field landed in the 42px slot and every colour rendered as a truncated "#FF". Pre-existing, and invisible until the panel got short enough to scroll to it.

2. Information architecture

  • The layer tree was permanently below the fold. Layers began at y=709 inside a 626px-tall panel, behind 449px of App Kit and 151px of Assets. The structure tree is the surface a designer touches most; Paper leads its left panel with it.
  • The empty state outweighed the tool. With nothing selected, Agent activity occupied 265px against the Inspector's 246px — a poster ("Select a frame, element, or connector.") beating the working panel. Paper's no-selection state is the Document state: page, zoom, and real controls.
  • Backup held 200px above the fold for information the status bar already reports.

3. Chrome weight

  • Seven ALL-CAPS icon headings stacked down each panel (APP KIT, ASSETS, LAYERS, INSPECTOR, AGENT ACTIVITY, FLOWS & CONNECTORS, BACKUP) plus caps on every field label. Paper's are sentence case at low weight.
  • A 64px top bar carrying a two-line brand block, because the board title stacked over a "⌂ Boards" sub-line that never read as navigation.
  • The selected element's name badge was a saturated accent pill sitting on top of the artwork — louder than the design it labelled, and spending the accent on something that isn't the active state.

The changes

  • shipped Drag-scrub numeric fields. The label is the handle — pointer-drag adjusts (2px per step, shift ×10), the input still takes an exact typed value. Two variants: a 24px gutter glyph where the letter is universal (X, Y, W, H) and a named row where it would be a guess (Stroke width, Corner radius, Opacity, Font size). A mystery glyph is worse than the row it saves.
  • shipped The wrapper is a <div>, not a <label>. Caught in verification: a label hands focus to its control on any click inside it, so finishing a scrub left the number input focused and swallowed the next ⌘Z, Delete, or arrow-nudge. The input carries its own aria-label.
  • shipped Inspector groups — collapsible Layout / Content / Appearance / Arrange bands, with Reference (internal id, hierarchy path) collapsed at the bottom. Agent identifiers stay one click away without leading the panel. Same treatment on the frame inspector.
  • shipped Colour rows fixed and compacted to name · swatch · hex on one 30px line.
  • shipped Nothing-selected renders a Document panel — board name, page, frame / element / connector / asset counts, zoom and Fit all — instead of a poster.
  • shipped Layers leads the left panel and flex-grows. Agent activity's empty state became a row; Backup starts collapsed.
  • shipped Sentence case app-wide (.panel-heading, .field span, pane labels, menu field labels) and a one-line breadcrumb brand (⌂ Boards › Board name) that let the top bar drop to 52px.
  • shipped The element name badge went neutral — a color-mix ink chip instead of an accent fill, so chrome stops out-shouting the artwork.

Verified: npm run typecheck, npm run build, npm test (73 passing); drag-scrub, focus behaviour, both themes, and a clean console checked in the running app.

One earlier read that was wrong

The floating zoom pill looked centred over the artboard in the first screenshot. It isn't — it is pinned to the canvas's bottom-right (right: calc(var(--right-panel-width) + 18px)), the same place Paper keeps its zoom control. No change made.

Feature gap — catalogued, not built

The user's instruction was to summarise these, not implement them. In rough order of leverage:

GapPaperPowerBoardWeight
CSS-native layoutFlex, gap, padding, constraints, clip; the canvas is HTML/CSSAbsolute x/y/w/h; layout exists in schema, renderer mostly ignores itLargest — architectural
Draw-to-create toolsTool rail: frame, rect, text, image, SVGClick a palette button; nothing is drawn on canvasHigh
Styling depthGradients, image fills, multiple fills, borders, shadow + inner shadow, filters, blend modes, per-corner radiusOne fill, one stroke, one radius, one opacityHigh
TypographyFull type panel, variable fonts, OpenTypeFont size only in the inspector (family / weight / line-height exist in schema, unexposed)Medium
Layer tree editingInline rename, drag reorder, drag reparent, search, filterNesting + lock/visibility/delete; rename via inspector; no drag reparentMedium
Canvas settingsPixel grid, snap-to-pixel, guides, nudge settings, invert zoomDot grid, snap guides on drag; no settings surfaceMedium
Multi-select inspectorMixed values, batch edit, selection colour inventory + replaceAlign/distribute + group/duplicate/delete onlyMedium
Import / generationFigma + SVG + web import, AI image and SVG generation, shaders, video exportImage and screenshot uploadLow — mostly outside PowerBoard's job
Where PowerBoard is aheadSemantic roles and hierarchy paths on every element; a validated operation model every writer shares; layout diagnostics and polish_layout self-correction; designed multi-agent presence (per-agent lanes, reticles, live feed); offline-first local storage with iCloud snapshots.

If one feature gap gets picked up next, it is CSS-native layout. It is the reason Paper's agent loop produces code that survives handoff, and it is the only item on the list that the rest depend on. Everything else is additive; that one is foundational.
